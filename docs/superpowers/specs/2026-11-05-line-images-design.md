# 行ごとの画像（line images）

## なぜ
撮影中に iPad で画像を見せるのをやめ、画像を動画に埋め込む（2026-11-05、Yuji の判断）。台本の行ごとに画像を 0〜1 枚指定し、その行の字幕が出ているあいだ表示する。

## 決まったこと（Yuji）
- 画像が 1 枚でも指定された回は、ステッカー・妖精・フィナーレを一切出さない。無い回は今までどおり。絵文字は台本に残り、アプリが出し分ける。
- 画像の指定は `send_to_teleprompter` の任意項目 `images`（`line` は 1 から数える）と、編集画面。
- クレジット不要の画像（CC0・パブリックドメイン・Unsplash・Pexels）を優先する。必要な回だけ、動画内の小さなクレジットとキャプションへの出典の自動追記を行う。
- 位置と大きさは決め打ちでよい。顔を隠さない。
- 受け取った時点で端末に保存し、撮影時・書き出し時にネットが無くても使えるようにする。

## 実装の形
- **受け取り**: `images: [{ line, url, credit?, source? }]`。サーバーは行番号・重複を検証し、`credit` のある画像だけ `画像: <credit> <source>` をキャプション末尾に足す。
- **保存**: ホームが受け取り箱を読んだ時点でダウンロードし、長辺 1280px に縮小して専用の IndexedDB に入れる。キーは URL（端末から選んだ画像は uuid）。Wikimedia のように CORS を許すサイトは直接、それ以外は `/api/image`（`Bearer` 認証、https のみ、名前解決の結果が公開アドレスのときだけ、4MB まで）を経由する。アプリは COEP: require-corp なので外部画像を `<img>` で直接は出せない。
- **台本**: `Script.lineImages: { en, imageId, url?, credit? }[]`。行番号ではなく行の文章に紐づける（`LineJapanese` と同じ考え方）。文章を直したときは `textSimilarity` で追いかける。
- **字幕との対応**: 字幕の数が台本の行数と同じなら順番で、違えば（文字起こしの字幕など）文章が一番近い字幕に対応させる。どの字幕にも対応しない画像は表示せず警告を出す。
- **書き出し**: `HookOptions.lineImages` に載せ、`withLineImages` がステッカーと妖精を切る。`renderSubtitleOverlays` が画像とクレジットを動画幅の透明 PNG にして字幕の下の層に足す。WebCodecs と ffmpeg のどちらの経路でも同じように動き、黒帯・look の上に出る（画像自体には色をかけない）。
- **カバー**: 先頭フレームにも入るので、画像がある回はステッカーを描かない。

## 配置（1080×1920）
- 通常は字幕のすぐ下: 字幕の下端から Instagram の 4:5 で切れる 85%（y 1632）まで、x 108〜972。枠の上端に寄せて置くので、字幕と画像がひとかたまりに見える。画像が出るのはその行のあいだだけなので、顔を隠してよい（2026-11-06、Yuji の判断）。
- 字幕の中心が高さ 50% より下の行は、字幕の下に場所がないので顔の上: 高さ 15.5〜31%（SNS で隠れる上部 15% と頭の先のあいだ）、中央、最大幅 620px。
- 書き出しの PNG は画像とクレジットの高さだけにする。重ね絵は書き出しのあいだ全部デコードされたままなので、枠いっぱいの透明 PNG にすると iPhone のメモリを食う。
- どちらも左右を 10% 以上空ける。TikTok は縦長のスマホで動画を拡大して左右を切るので、右端まであった以前の「顔の右」の枠は画像が切れていた。

## やらないこと
- 画像の検索（アプリは受け取るだけ。探すのは Claude のネタ出し）
- 位置・大きさの手動調整、撮影画面（読み上げ）への画像表示
- バックアップへの画像本体の同梱（URL から取り直す。端末から選んだ画像は選び直し）
